# Introducción
El conflicto armado en Colombia ha generado profundas brechas sociales, afectando de manera significativa el acceso y la continuidad en los procesos educativos de miles de personas. Esta situación ha limitado el desarrollo personal, profesional y económico de las poblaciones más vulnerables, especialmente aquellas en condición de desplazamiento o en proceso de reincorporación social.
En este contexto, la restitución del derecho a la educación se convierte en un eje fundamental para la reparación integral, permitiendo no solo la adquisición de conocimientos, sino también la reconstrucción del proyecto de vida de los individuos. Sin embargo, la falta de herramientas tecnológicas centralizadas dificulta la identificación del nivel académico de estas personas y su vinculación efectiva a programas educativos.
Frente a esta problemática, surge el proyecto Fortress Educa, el cual propone el desarrollo de un sistema web que facilite el diagnóstico académico, la orientación educativa y el seguimiento del proceso de reintegración mediante un sistema estructurado de gestión de solicitudes. Esta solución busca optimizar la interacción entre los usuarios y las rutas educativas disponibles, fortaleciendo los procesos de inclusión social a través de la tecnología.

La restitución del derecho a la educación se convierte en un elemento clave dentro de los procesos de reparación integral, contribuyendo a la reconstrucción del tejido social y a la generación de garantías de no repetición.

## Seguridad de Aplicaciones
### Manejo de Errores
Se diseñó e implementó un sistema de manejo de errores HTTP que abarca tanto errores del cliente (códigos 4XX) como del servidor (códigos 5XX), con el objetivo de evitar interrupciones inesperadas en el funcionamiento del aplicativo web y mejorar la seguridad ante intentos de acceso no autorizados o solicitudes inválidas.
Este sistema permite capturar y gestionar de forma controlada las excepciones generadas durante la ejecución de la aplicación, mostrando respuestas adecuadas al usuario en lugar de mensajes de error abruptos o confusos.
La implementación se realizó utilizando la clase HTTPException de la biblioteca Werkzeug, la cual está integrada en el framework Flask. Esta herramienta permite generar excepciones que son automáticamente transformadas en respuestas HTTP válidas, con su respectivo código de estado y mensaje asociado.

### Seguridad de Contraseñas
Se implementó un mecanismo seguro para el almacenamiento de contraseñas basado en SALT + HASH + PEPPER, evitando guardar información en texto plano y protegiendo contra ataques como fuerza bruta o tablas rainbow.
Para ello, cada contraseña se transforma mediante el uso de Argon2 con un salt único por usuario y un pepper almacenado de forma externa, se genera un hash seguro de la contraseña, que junto al hash del salt, se almacena en la base de datos.
Para el proceso del hash, se desarrolló una función global reutilizable para los procesos de registro, inicio de sesión y recuperación de contraseña, encargada de generar o recuperar el salt y calcular el hash correspondiente. Asimismo, se implementó una función de validación que compara el hash almacenado con el generado a partir de la contraseña ingresada.
Las pruebas realizadas confirmaron el correcto funcionamiento del sistema, generando hashes válidos y consistentes, ver Figura 13.

## Servidor AWS
El despliegue y funcionamiento de la aplicación web se realizó utilizando servicios de computación en la nube proporcionados por Amazon Web Services (AWS). La solución se basa en una instancia EC2 como servidor principal, donde se ejecuta la aplicación sobre un sistema operativo Linux. La arquitectura integra la base de datos MySQL en el servicio RDS para el almacenamiento de la información y un bucket de Amazon S3 para el almacenamiento de archivos y copias de seguridad.
Figura 24
Arquitectura General del Sistema en AWS

La arquitectura del sistema se diseñó bajo los servicios Amazon EC2, Amazon S3 y una base de datos MySQL. La instancia EC2 actúa como núcleo de procesamiento, ver Figura 25, alojando la aplicación backend desarrollada en Flask y gestionando la lógica de negocio. Amazon S3 se integra como servicio de almacenamiento para archivos no estructurados, tales como evidencias fotográficas o documentos asociados a los reportes, evitando sobrecargar el sistema de archivos local de la instancia.
 El servicio RDS permite alojar la base de datos MySQL. La comunicación entre los componentes se realiza de manera directa y segura dentro de la misma VPC, garantizando baja latencia y simplicidad operativa.
